# A3 : Modèle C4, niveaux 1 et 2 (brouillon)

Sources : `diagrammes/c4-contexte.puml`, `diagrammes/c4-conteneurs.puml`.

## Niveau 1 : contexte

| Élément | Type | Rôle |
|---|---|---|
| Personne étudiante | Personne | Construit et suit son plan |
| Personne qui encadre | Personne | Répond aux demandes, fixe sa capacité |
| Conseil de programme | Personne | Définit les règles de programme |
| Plateforme de planification | Système visé | Voir les cas A1 |
| Registrariat | Système externe | Valide les inscriptions |
| Répertoire des cours | Système externe | Fournit cours et exigences |
| Calendrier officiel | Système externe | Fournit les dates limites |

Les trois systèmes externes sont **simulés** dans le prototype (`TEMP(registrariat)`,
`TEMP(répertoire)`, `TEMP(calendrier)`).

## Niveau 2 : conteneurs

| Conteneur | Technologie | Justification (une phrase) |
|---|---|---|
| Application web | Django (Python), gabarits côté serveur, authentification Django | Un seul conteneur couvre domaine, règles et pages, ce qui garde la conception lisible. |
| Base de données | SQLite (dev), PostgreSQL envisagé en production | Zéro installation pour le prototype, migrations Django portables. |
| Données de démonstration | Commande Django `seed` | Rend le monde simulé reproductible (`TEMP(données)`). |
| Moteur de règles | Module Python dans l'application | Règles lues depuis la base, modifiables sans changer le code (N-02). |

Relations (étiquette : ce qui circule, par quel moyen) :
- Personne étudiante → Application : formulaires et pages, HTTPS.
- Personne qui encadre → Application : réponses aux demandes, HTTPS.
- Conseil de programme → Application : règles du programme, HTTPS (administration Django).
- Application → Base : lecture et écriture des plans et demandes, ORM Django.
- Application → Registrariat : demande d'inscription et motif de rejet (`TEMP`, simulé).
- Application → Répertoire des cours : lecture des cours et exigences (`TEMP`, données dans la base).
- Application → Calendrier officiel : lecture des dates limites (`TEMP`, données dans la base).

Cohérence avec A1 : chaque cas CU1 à CU11 est servi (CU11 par l'interface d'administration Django) par l'Application web ; CU2 passe par le
Répertoire des cours, CU7 par le Calendrier officiel et CU9 par le Registrariat.
